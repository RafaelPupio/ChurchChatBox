# Backlog

The longer wishlist. **Nothing here is committed** — v1 is deliberately small (see [[Overview]]).

## Likely next, once v1 is live
- **Sub-menus (`submenu` kind)** — the escape hatch when the church outgrows the 10-row list. See [[Menu Inventory]].
- **Multi-church onboarding UI** — the schema already supports it; only the UI is missing. This is the "product later" step. See [[Decisions Log]].
- **Prayer request notifications** — ping a staff member's WhatsApp when a request arrives, instead of waiting for someone to open the panel.
- **Basic analytics** — which menu items get used? Would tell the church what members actually want, and what to delete.

## Considered and parked
- **AI free-text answers** — deliberately rejected for v1 (menu-only). Revisit *only* if members keep typing questions the menu can't answer. That's a real signal; anything else is novelty.
- **Broadcasts / avisos to members** — costs money per message and needs Meta template approval. Also the fastest way to make a church number feel like spam.
- **Event registration / member database / giving records** — a different product. Don't smuggle it in.

## Won't do
- **Baileys or any unofficial WhatsApp library** — bans the number. Settled, see [[Decisions Log]].
- **Using the church's existing number** — irreversible, see [[Meta WhatsApp Setup]].
